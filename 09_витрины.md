# Этап 9. Аналитические витрины

**Команда 06 · «Доставка посылок»**

> Этап 9. Собрать одну или несколько аналитических витрин, пригодных для анализа предметной области.
> Витрина должна позволять отвечать на осмысленные бизнес-вопросы без повторного разбора RAW.

Код: `sql/07_marts.sql`. Шаг pipeline — `core.step_06_build_marts()`.
Витрины строятся только из очищенного core; показатели качества — из итогов обработки строк (`core.stg_event_clean`).
RAW повторно не разбирается. При каждом запуске витрины полностью пересобираются, поэтому повторный запуск даёт те же данные.

## 1. Состав

| Витрина | Зерно | Строк | Для чего |
| :--- | :--- | ---: | :--- |
| `core.mart_shipment` | 1 посылка | 2 000 | жизненный цикл посылки: участники, маршрут, время каждого этапа, последний статус, срок, полнота, качество данных |
| `core.mart_route_daily` | маршрут × день создания | 807 | загрузка маршрутов по дням, доля дошедших до курьера, средний срок |
| `core.mart_courier_daily` | курьер × день передачи | 298 | нагрузка на курьеров |
| `core.mart_event_daily` | день × этап | 74 | поток событий по дням и этапам |

## 2. `core.mart_shipment`

| Поле | Смысл |
| :--- | :--- |
| `shipment_id` | номер посылки `PKG-NNNNNN` (PK) |
| `sender_id`, `sender_name`, `sender_city` | отправитель: номер, ФИО, город |
| `receiver_id`, `receiver_name`, `receiver_city` | получатель |
| `courier_id`, `courier_name` | курьер (NULL, если не определён) |
| `route_id`, `route_name`, `from_city`, `to_city` | маршрут, `route_name` = «Москва → Казань» |
| `is_same_city`, `is_self_shipment` | внутригородская посылка; отправитель = получатель |
| `created_at` … `handed_to_courier_at`, `delivered_at` | время каждого этапа (NULL — этап не загружен) |
| `first_event_at`, `last_event_at`, `first_event_date` | первое и последнее событие |
| `last_status_code`, `last_status_name`, `last_status_seq` | последний загруженный этап |
| `events_loaded`, `stages_loaded`, `missing_stages` | событий в core; различных базовых этапов (из 5); коды отсутствующих |
| `is_complete_chain` | загружены все 5 базовых этапов |
| `reached_courier` | есть событие «Передано курьеру» |
| `lead_time_hours` | срок «Создано» → «Передано курьеру», часов |
| `event_flags`, `shipment_flags` | флаги качества событий (кол-во) и посылки (список) |
| `raw_rows`, `quarantined_rows`, `duplicate_rows` | строк RAW с этим номером посылки, из них в карантине и дублей |

Пример строки:

| shipment_id | route_name | sender_name | courier_name | created_at | handed_to_courier_at | lead_time_hours | is_complete_chain |
| :--- | :--- | :--- | :--- | :--- | :--- | ---: | :---: |
| PKG-900001 | Санкт-Петербург → Москва | Петров Сергей Сергеевич | Зайцев Наталья Михайловна | 2026-01-01 08:10 | 2026-01-02 16:10 | 32.00 | t |

## 3. Агрегированные витрины

**`core.mart_route_daily`** (PK `report_date, route_id`): `route_name`, `from_city`, `to_city`, `shipments`, `reached_courier`,
`complete_chain`, `without_courier`, `events_loaded`, `quarantined_rows`, `avg_lead_time_hours`.
День — дата первого загруженного события посылки.

**`core.mart_courier_daily`** (PK `report_date, courier_id`): `courier_name`, `shipments`, `handed_events`, `routes`, `cities`,
`avg_lead_time_hours`. День — дата передачи курьеру; если этот этап в карантине — дата последнего события посылки.

**`core.mart_event_daily`** (PK `event_date, status_id`): `status_code`, `status_name`, `events`, `shipments`, `flagged_events`.

## 4. Сверка с core

Витрины сверяются с core проверками 19–22 этапа 8 и запросом `core.v_q10_reconciliation`:

| Сверка | Витрина | Core |
| :--- | ---: | ---: |
| посылки: `mart_shipment` = `core.shipment` | 2 000 | 2 000 |

## 5. Особенности данных, видные в витринах

* В RAW нет ни одной настоящей доставки. Из 60 строк «Доставлено» 58 в карантине: у 53 основная причина
  `STATUS_MISLABELED` (метка стоит на месте базового этапа), у 5 — ошибка даты. Ещё 2 строки — точные дубли. Поэтому `delivered_at` пуст, а конечная точка цикла — «Передано курьеру».
* События посылки идут с шагом ровно 8 часов (проверка `ts_vs_8h_rule` в `sql/03_tests.sql`).
  Поэтому у всех 1 528 посылок, где есть и «Создано», и «Передано курьеру», срок равен 32 ч.
* 974 посылки без части этапов: эти строки RAW ушли в карантин (дата, статус) или были дублями.
